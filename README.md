# userdrv

BORUIX 的用户态驱动模板：演示一个驱动如何在用户态认领真实硬件、映射寄存器并读写。

[English](README.en.md)

## 它是什么

这不是一个真实驱动，而是骨架：演示完整的调用序列——查询设备、登记、认领、映射寄存器、读硬件。
内核只保留「访问硬件的权限」的授予；驱动主体逻辑完全在用户态运行，出错只影响本进程。

## 两种模式

- **瞬态**——登记、认领、读一次寄存器、释放、退出。用于手动验证与自检
- **长驻**——命令行以 `resident:<设备名>` 开头时进入：保持认领不释放，约每 2 秒读一次寄存器
  作为心跳，证明驱动在持续服务

## 权限

登记与认领设备是受限操作：以普通用户身份运行会收到「权限不足」并如实报错退出。能认领硬件的
程序可以直接操作硬件、不受普通文件权限约束，这个限制是必要的。

## 已知限制

- 心跳读的是寄存器真值，但不驱动任何具体硬件行为；真实驱动以此骨架为起点补协议实现
- 长驻模式没有主动退出路径，被终止后设备由内核自动释放

## 构建

```bash
cargo build --release
```

## 文件结构

```
userdrv/
├── Cargo.toml    # 包定义
├── build.rs      # 注入链接脚本
├── linker.ld     # 用户态段布局
└── src/
    └── main.rs   # 两种模式的驱动骨架
```
